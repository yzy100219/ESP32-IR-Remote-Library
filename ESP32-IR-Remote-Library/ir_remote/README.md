# ESP32 红外接收库 (基于 RMT 硬件外设)

这是一个专为 ESP-IDF 框架设计的纯 C 语言红外接收库。采用底层 RMT 硬件外设，配合 FreeRTOS 中断与队列解耦，**不占用 CPU，不阻塞主循环**。
esp-idf版本为v5.3.6
---

## ✨ 功能特性
- **硬件级接收**：使用 ESP32 RMT 外设，精准捕捉微秒级红外脉冲。
- **自适应 NEC 协议**：内置智能解析算法，兼容部分引导码丢失及毛刺杂波。
- **长按判定**：自动识别标准 NEC 长按重复码。
- **极简 API**：一行代码即可获取按键值，完美适配小白。

---

## 🔌 硬件接线
以常见的 3 脚红外接收头（如 VS1838B）为例：
- **VCC** -> 接 ESP32 的 `3.3V` (切勿接 5V，容易烧坏引脚)
- **GND** -> 接 ESP32 的 `GND`
- **OUT (Data)** -> 接 ESP32 的任意 GPIO（推荐避开专用引脚，如示例用 `GPIO 17`）

## 🚀 快速开始

### 1. 引入组件
将 `ir_remote` 文件夹放入你的工程 `components/` 目录下。

### 2. 代码示例
```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "ir_remote.h"

#define IR_RX_GPIO 17 // 你的红外接收引脚

void app_main(void)
{
    // 1. 初始化红外模块，传入引脚号
    IR_Remote_Init(IR_RX_GPIO);

    while (1) {
        // 2. 极简轮询（非阻塞，没有按键时返回 0xFF）
        uint8_t cmd = IR_Remote_GetCommand();
        
        if (cmd != 0xFF) {
            printf("收到按键码: 0x%02X\n", cmd);
        }
        
        // 3. 释放 CPU
        vTaskDelay(pdMS_TO_TICKS(20)); 
    }
}

🛠️ 调试与进阶指南（进阶玩家必读）
当你在使用未知的遥控器（如空调遥控器、杂牌电视遥控器）时，可能会发现代码没有输出，或者解析失败。别慌，以下是排查指南。

1. 如何开启串口查看原始红外数据？
很多复杂的协议（如格力、美的空调）不是标准的 NEC 协议，数据帧极长。为了破解它们，你需要把底层收到的时间脉冲原封不动地打印出来。

打开 ir_remote.c 文件，找到顶部的宏定义：

c
#define DEBUG_IR_RAW          1  // 改为 1 开启调试，改回 0 关闭（发布时请关闭）
将 0 改为 1，重新编译烧录。按下遥控器，你的串口监视器（如 idf.py monitor）会打印类似如下的数据：

text
I (1234) IR_RAW: 收到脉冲！共 37 个符号
I (1235) IR_RAW:   [0] L0:0 T0:8943 us | L1:1 T1:4472 us
I (1236) IR_RAW:   [1] L0:0 T0:566 us | L1:1 T1:529 us
I (1237) IR_RAW:   [2] L0:0 T0:593 us | L1:1 T1:527 us
怎么看？ T0 和 T1 代表电平持续的微秒数（us）。

标准 NEC 特征：第一段通常以 9000us (9ms) 和 4500us (4.5ms) 开头。

2. 为什么我的空调遥控器解不出来？
空调遥控器不用 NEC 协议！
电视和风扇通常是“按一下发一个短指令”（NEC协议）。而空调遥控器按“温度+”，它会发出一整包极长的数据（包含当前模式、温度、风速、扫风等，甚至带有复杂的校验码）。

如果你用 DEBUG_IR_RAW = 1 打印空调遥控器，你会发现两个现象：

数据极长：可能收到 200 甚至 300 多个符号。

没有标准引导码：第一段可能不是 9ms，而是 4.5ms 或其他数字。

如何解决？
本库自带的 IR_ParseNEC 只是用来抓普通按键的。如果你想破解空调：

将 ir_remote.c 里的 RMT_RX_MAX_SYMBOLS 改大（例如 512），防止长帧被截断。

开启 DEBUG_IR_RAW，自己打印长帧数据。

自己写一个解析函数，比对两次按“温度+”的数据，找出哪几个字节发生了变化，并尝试逆推它的校验和算法（网上有很多大佬的开源代码可以参考，如果是格力/美的，建议直接用 C++ 的 IRremoteESP8266 库，那个已经封装好了）。

⚠️ 常见问题排查
按下遥控器毫无反应（连原始数据都不打印）：

用手机摄像头对准红外发射管，按按键看是否有紫光闪烁，确认遥控器有电且没坏。
检查 VCC 和 GND 是否接反。
检查 IR_RX_GPIO 的宏定义是否与你实际接线一致。
解析结果偶尔乱码/失败：
可能是电源干扰。建议在红外接收头的 VCC 和 GND 之间并联一个 0.1uF 的电容，或者将红外接头的线尽量缩短。
